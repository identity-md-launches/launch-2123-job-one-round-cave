# Core Audit

Independently check a saved Conflict Core schema-1 report: bind it to its finite
catalog, verify every supplied root-removal witness, and exhaustively check the
claimed core's impossibility without calling the resolver's search or predicate.
This closes the earlier Exhaustive Audit limitation: it checked the whole catalog
but did not bind or establish a saved core's irreducibility.

From the repository root, using Python 3.9+ and only its standard library:

```sh
python3 -B line-4/tools/core-audit/check_core.py demo
```

Observed: `verified`, with both removal witnesses checked and all **108**
Cartesian assignments exhausted for the historical Requests 2.25.1 / idna >=3.10
conflict. Removing either core root admits the recorded compatible assignment.
The report is bundled in `examples/requests-report.json`, generated by the
unchanged Conflict Core tool from its stored real Requests metadata projection.
No live metadata or installed package data is read. These are historical finite
compatibility facts, not recommendations about today's releases.

For your own workspace-local inputs:

```sh
python3 -B line-4/tools/core-audit/check_core.py catalog.json --report report.json --max-assignments 10000
```

Keep sibling `exhaustive-audit/` and `offline-resolver/` folders. See Offline
Resolver's README for the numeric version grammar and catalog format. The loader
rejects duplicate JSON keys, oversized files and paths resolving outside the
current workspace. The audit writes only JSON to stdout; it does not install,
execute packages, read environment variables/configuration, or use a network.

Exit 0: verified; 1: rejected with a compatible core counterexample; 2: invalid
input or report (including stale binding or false removal witnesses); 3:
inconclusive because the assignment budget ran out. Exact budget exhaustion
that completes enumeration is accepted. `--max-assignments 107` on the demo
returns inconclusive; 108 suffices. Budgets accept 1–1,000,000 and count candidate
tuples, not elapsed time, memory, graph construction or edge checks.

An `irreducible` claim requires exactly one valid reachable assignment for each
single-root removal. Monotonicity under removing roots then establishes that
every proper subset is compatible. This does **not** establish smallest core
cardinality among other cores, or recommend which root to remove. A report with
`minimality: inconclusive` may omit witnesses: the result can verify impossibility
but explicitly sets `irreducible_verified: false`. It does not upgrade the claim.
Trials, search counters, representative conflict and prose are not audited.
SHA-256 binding authenticates neither publisher nor provenance.

The Cartesian enumerator and edge checker are distinct from the resolver search,
but share its parser. Enumeration is exponential; incomplete enumeration proves
nothing about impossibility. Full package ecosystem syntax, platform markers,
artifacts, installability, security and catalog completeness remain outside scope.
Stable input files are assumed; reads are not atomic snapshots.

Checks:

```sh
python3 -B -m unittest discover -s line-4/tools/core-audit -p 'test_*.py' -v
```

Ten tests passed: stored real evidence, 300 seeded catalog comparisons, false

exact budget boundaries, immutable inputs, and disabled original search/predicate.
These are local regression observations, not independent certification.
